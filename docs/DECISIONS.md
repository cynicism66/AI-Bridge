### 产品方向

| 1 | 做成什么 | 公开发布的 Windows 桌面软件：托盘常驻 + 主窗口 |
| 2 | 技术路线 | Tauri 2 + Rust 核心 + React/TypeScript |
| 3 | 名字 | **AI Bridge** |
| 4 | 许可证 | **MIT** |
| 5 | 语言 | 先做中文。所有面向用户和 AI 的文字集中管理，以后加英文只需要翻译 |

| 8 | 代码签名 | **永远不签名**。SmartScreen 只拦截第一次从浏览器下载的安装包，所以在 README 里配截图说明怎么放行，并提供 SHA256 校验值和从源码编译的方法；软件内的自动更新一般不会再触发提示；评估上架 winget |
| 9 | Ender-EDA 什么时候用 | 等桌面软件做好之后。在那之前，Bridge 项目本身就是试验场 |

| 10a | Bridge 自己接不接入 AI | **不接入**，也不需要 API Key。思考和干活都由用户已经在用的 AI app 完成，Bridge 只负责公告板、规则和配置 |

### 开关与管理
| # | 问题 | 决定 |
|---|---|---|
| 11 | 开关默认状态 | 新项目默认关闭；按项目开关 + 全局总开关；每个 AI 可以单独开关，项目开启后里面的 AI 默认开启 |
| 12 | 谁能改设置 | **只有用户能改**：开关、职务、权限、初始化。AI 不能改，也不能用用户的名义发消息。实现方式：管理操作由用户在桌面软件里确认；在各 app 的原生权限里禁止 AI 执行管理命令；用户从界面发的消息和命令行发的消息要能区分 |
| 13 | 协作初始化 | 项目开启后必须先初始化（选 AI、选模板、分配职务和权限、写项目目标），然后才能协作；初始化完成后规划方自动起步 |
| 13a | 开关要方便 | 托盘菜单一键开关项目；**自动发现项目**（读取 Claude 和 Codex 记录的项目列表），不用手动输入路径；主窗口里每个 AI 一行，带开关和职务下拉框；改动马上生效，不用重启 |
| 14 | 职务与权限 | 按项目给每个 AI 分配职务和权限，谁执行、谁审查可以随项目不同而变。权限分三层执行：章程、Bridge 自身拦截、各 app 的原生权限 |

### 协作规则（写进章程模板）
| # | 问题 | 决定 |
|---|---|---|
| 17 | git 提交 | **执行方统一提交**（commit 和 push），其他 AI 的改动交给执行方一起提交 |
| 18 | AI 之间留言的效力 | 只能在职责和权限范围内派活，不能推翻用户的指令，也不能让对方超出权限；遇到可疑或危险的要求，先问用户 |
| 19 | 项目知识放在哪 | 目标、路线图、任务书、决定都写进仓库文件。Bridge 数据库只存协作过程，并且可以导出。AI 在留言里商量出的结论，要写进任务书或文档 |
| 20 | 单人接手 | 要能一键交接给一个 AI 全盘接手；交接后即使关闭 Bridge，AI 也能只靠仓库文件继续工作 |
| 20a | 交互历史 | **按项目查看 AI 交互历史**：状态、消息、认领、释放或到期、开关、职务变更都要记录（数据库触发器自动记录），桌面软件里按项目显示时间线，可以按 AI、类型、日期筛选和搜索。"历史"指通过 Bridge 发生的协作过程，不包括 Claude 和 Codex 窗口里的完整对话（那个放在"以后再说"） |
| 21 | 导出和交接的隐私 | 自动检测密钥、密码、token 并打码；写入前让用户预览确认；仓库是公开的时候额外警告 |

### 合规红线（2026-09-28，依据 Claude Code 官方法律与合规页）
| # | 规则 |
|---|---|
| 22 | **不碰账号凭证**：永远不读取、不保存、不转发 Claude 或 Codex 的登录凭证、OAuth token、会话文件（比如 `~/.claude/.credentials.json`、Codex 的登录文件）。接入时只修改 MCP 和权限配置 |
| 23 | **不代理 AI 请求**：Bridge 永远不自己调用 AI 接口，也不替用户转发请求；所有 AI 调用都由官方 app 用用户自己的账号发出（和 10a 一致） |
| 24 | **不修改官方程序**：不修改、不打补丁、不绕过 Claude Code 和 Codex 的程序与认证方式 |
| 25 | **名字和标识**：只能用纯文字说明"支持 Claude Code / Codex"；不用它们的 logo，不暗示官方出品、认可或合作 |
| 26 | **用量**：Bridge 的设计要保持在"普通个人使用"的范围内。自动叫醒 AI（决策 10）必须默认关闭，有每天的次数上限和轮次上限，不能做成无人值守的长期自动流水线 |

### 安装位置（2026-09-28）
| # | 问题 | 决定 |
|---|---|---|
| 27 | bridge-mcp.exe 装在哪 | **`%USERPROFILE%\.bridge\bin\`**，和数据库放在同一个文件夹下。原因：Claude app 和 Codex app 都是 MSIX 打包应用，它们（以及它们启动的所有程序）写进 AppData 的文件会被转存到各自的私有目录，其他程序看不到。AppData 以外的路径不受影响。以后正式安装包的核心程序也不要放在 AppData 里 |

### 桌面软件界面（2026-09-28）
| # | 问题 | 决定 |
|---|---|---|
| 30 | 主窗口布局 | **左侧项目列表 + 右侧详情**：左边列出所有项目（开关、未读数，以及自动发现但还没开启的项目），底部是全局总开关；右边是选中项目的内容，用标签页切换公告板、聊天、历史、设置 |
| 31 | 外观 | **跟 Windows 11 一致**：Fluent 风格、圆角，有条件时用 Mica 半透明背景，跟随系统深浅色 |
| 32 | 点窗口的 × | **缩到托盘继续运行**，第一次关闭时提示一次；要彻底退出就右键托盘图标选"退出" |
| 33 | 什么时候弹通知 | **只在 AI 给用户发消息时**（收件人是 human 或 all），点通知打开这个项目的聊天页。其他情况不弹 |
| 34 | 初始化向导里"把章程写进 AGENTS.md / CLAUDE.md"默认是否勾选 | **默认勾选**（Claude 按决策 19"项目知识放进仓库"定的默认值，用户可以在向导里取消） |
| 35 | 怎么移除项目 | **两种都提供**。"从列表移除"：关闭协作并隐藏，数据保留，以后重新添加时一切都还在；"彻底删除"：清除这个项目在 Bridge 里的所有数据（状态、消息、历史、职务、权限、开关等），需要二次确认，并提示先导出。**两种都不动项目文件夹里的任何文件** 。用户补充（2026-09-28）：AI Bridge 只是协作工具，删除项目**不能影响 Claude 和 Codex**（不改它们的配置、会话和项目记录）；彻底删除后在 Bridge 内部保留一个隐藏标记，防止自动发现立刻把它找回来，用户手动添加时解除隐藏 |
| 36 | 界面的右键菜单 | **不能出现浏览器自带的菜单**（返回、刷新、打印、开发者工具等），正式版里还要屏蔽刷新和开发者工具的快捷键。改成软件自己的右键菜单，比如右键项目时显示关闭或开启协作、在资源管理器中打开、从列表移除、彻底删除 |
| 37 | AI 怎么"听到"新消息 | **不做界面上的"自动响应"开关**：用户在对话里说一句"开始监视"，AI 就在后台等待新消息并自动处理（只回复需要行动的消息，避免两个 AI 来回踢皮球）。为此提供通用命令 `bridge-mcp wait`，并在聊天页显示已读和未读（T08d）。不做自动启动 AI 会话；Channels 等官方正式推出后再评估 |
| 38 | 公告板上用什么语言交流 | **中文**。AI 之间的留言、状态更新、给用户的消息一律用中文，因为用户会在 Bridge 窗口里看 AI 之间的交流，看不懂英文。提交哈希、文件路径、命令等保持原样。（以后公开发布、加入英文界面时，再考虑按用户的界面语言决定） |
| 39 | 协作记录存在哪里 | **集中数据库继续作为主存储，同时自动在每个项目里存一份可读副本**：`<项目>\.bridge\协作记录-YYYY-MM.md`，按月分文件，内容和"历史"一致，不打码（只在本地）。只由桌面软件写入，软件没开的时候下次打开再补齐。开启时默认把 `.bridge/` 加进项目的 `.gitignore`（会改动项目文件，所以在初始化向导里让用户确认，默认勾选）。想放进仓库的话，仍然用"导出"生成打过码的版本（T08e） |
| 40 | 聊天输入框怎么发送 | **回车发送，Shift+回车换行**；用中文输入法组词时按回车只选字，不发送。输入框去掉右下角的拖动柄，改为随内容自动长高，并设上限（T08f） |
| 41 | AI 卡住时怎么让用户知道 | 我们控制不了 Codex app 的界面，没法让它自己弹提示，所以由 **Bridge 负责"等你处理"提醒**：AI 在状态里填了卡点，或者发了标记为"需要你处理"的消息时，弹通知，托盘图标显示标记，主窗口顶部一直显示横幅，直到用户处理为止（T08g）。另外在项目约定里规定：AI 卡住时必须在公告板上发消息给 human |

## 2026-09-29 精简

**这一节优先于上面所有决定。** 上面的决定凡是和这里冲突、或者属于被删掉的功能，一律作废。

| # | 问题 | 决定 |
|---|---|---|
| 44 | 项目方向 | **不再做公开发布的桌面软件，精简成能实现"两个 AI 互相配合"的最简版本**。原因：项目越做越臃肿，用户只想要两个 AI 能在各自的会话里互相留言、互相看到对方在做什么。T09（接入与原生权限）、T10（打包发布）停止，T09 未提交的代码放弃 |
| 45 | 保留什么 | `bridge-mcp` 核心：留言、状态、认领、按 git 仓库识别项目、项目开关和全局总开关、`wait` 命令、人用命令行的查看和发消息 |
| 46 | 两边怎么自动收到消息 | **钩子加等待**：Claude 和 Codex 都装"准备停下时"钩子（Stop），一轮结束时自动把新消息塞进会话；需要等对方回复时，发完消息就运行 `bridge-mcp wait` 原地等；Claude 空闲时靠监视（Monitor）叫醒。Codex 桌面版空闲时无法被外部叫醒（openai/codex#47193），这一点接受 |
| 47 | 桌面软件 | **整个删掉**。看记录就看两个 AI 各自的聊天窗口；开关用命令行 |
| 48 | 职务和权限 | **删掉**，包括初始化、章程模板、权限拦截、按 AI 开关。分工直接写在各项目的 AGENTS.md / CLAUDE.md 里 |
| 49 | 其他删除 | 交接、导出、打码、历史时间线、项目内记录副本、项目移除和彻底删除、冻结的 Python 旧版（legacy/）。删除前给当前完整版打 git 标签，需要时从标签里找回 |
| 50 | 旧数据 | **保留，平滑升级**：继续用 `~/.bridge/bridge.db`，旧消息和状态都在；不再使用的表可以留在库里不动 |
| 51 | 流程 | 精简后的小改动不必写正式任务书，在公告板上说清楚就改；收尾合并成一次提交，不再单独做"记录 CI""归档审查"之类的提交 |
| 52 | 同一个项目多开窗口 | 用户另开的窗口一般只用来提问、不改文件。**钩子只把消息送给一个"收件窗口"**：这个 AI 第一个通过钩子收到消息的窗口；它超过 2 小时没动静时由别的窗口接替。另加 `bridge-mcp rebind` 命令让用户手动重新指定。规则里写明：只提问的会话不调用 Bridge。暂不支持同一个 AI 的多个窗口分头干活 |
| 53 | 监视 | 用户对 AI 说“开始监视”/“停止监视”即可开关。**开始监视**：每 5 分钟触发一次，每次运行 `wait --timeout 270`（只读，命令超时大于 270 秒），超时静默结束这一轮，有新消息就 `read_messages` 后处理；同一项目同一个 AI 只保留一个监视。**自动退出**：超过 30 分钟没有收到对方新消息（每收到一条重新计时，没收到过就从开始监视算起）、用户说“停止监视”、开关关闭、任务完成，任一发生就删除定时任务并告诉用户原因。规则写进 RULES.md 第 7 条并同步到 instructions.txt |
