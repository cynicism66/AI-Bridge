# Bridge 路线图

## 目标
让在同一个项目里工作的多个 AI（Claude、Codex）能够：
1. 看到彼此在做什么（状态）
2. 互相留言、交接（消息），人也可以参与
3. 避免同时改同一个文件（认领）

并且做成**公开发布的 Windows 桌面软件**（用户在 2026-09-27 拍板）：
- 托盘常驻，AI 给人发消息时弹出通知；主窗口里可以开关项目、查看公告板、聊天
- 双击安装，自动接入 Claude 和 Codex；卸载时还原
- 技术路线：Tauri 2 + Rust 核心 + React/TypeScript 界面

架构说明见 [ARCHITECTURE.md](ARCHITECTURE.md)，用户的决定见 [DECISIONS.md](DECISIONS.md)（和本文冲突时以决策记录为准），T06–T09 的具体设计见 [design/协作初始化与交接.md](design/协作初始化与交接.md)。

## 设计原则
- **项目知识必须存在仓库里**：目标、路线图、任务书、完成报告、审查意见、关键决定都要写进仓库文件。Bridge 数据库只存协作过程，并且可以随时导出。AI 在留言里商量出的结论，要写进任务书或文档。这样任何一个 AI 都能不依赖 Bridge 接手项目。
- **Bridge 自己不接入 AI**：思考和干活的都是用户已经在用的 AI app，Bridge 只负责公告板、规则和配置。
