# T08a：桌面软件骨架、托盘、公告板与聊天

## 背景
依据：DECISIONS 第 1、2、5、12、13a、22、30–33 条。T08 拆成两步：
- **T08a（本任务）**：搭好 Tauri 应用；项目列表和各级开关；托盘；公告板；聊天；通知；自动发现项目。
- **T08b**：初始化向导、职务和权限的编辑、历史时间线、导出和交接的界面。

## 一、技术栈和依赖（允许的清单）
- 目录 `app/`：`app/src-tauri`（Rust，加入 workspace，依赖 `bridge-core`），`app/src`（React + TypeScript + Vite）。
- **Rust**：`tauri`（Tauri 2，开 `tray-icon` 特性）、`tauri-build`、`tauri-plugin-notification`、`tauri-plugin-single-instance`、`tauri-plugin-dialog`。
- **npm**：`react`、`react-dom`、`@fluentui/react-components`、`@fluentui/react-icons`、`@tauri-apps/api`，以及上面三个插件对应的 JS 包；开发依赖：`vite`、`@vitejs/plugin-react`、`typescript`、`vitest`。锁文件（`Cargo.lock`、`package-lock.json`）要提交。
- 除此之外的依赖，需要先在完成报告里说明理由。
- **安全**：Tauri 的 capabilities 只开启真正用到的权限，不开 shell，不开宽泛的文件系统权限；配置严格的 CSP。前端只能通过自己定义的 Tauri 命令访问数据。

## 二、bridge-core 结构化接口
现在给人用的接口（`human.rs`）只返回文字，界面需要结构化数据。在 `bridge-core` 里新增接口，返回可以序列化成 JSON 的结构体，**命令行继续用原来的文字输出，逻辑不能重复写两遍**：
- 项目列表：每个项目的项目键、开关状态、初始化状态、未读数（发给 human 或 all、human 还没读的消息数）、最近活动时间
- 全局开关的读写
- 项目详情：章程版本和摘要、各方职务，以及每个 AI 的开关、各会话的状态（编号、分支、文件夹、任务、进度、卡点、下一步、更新时间）、当前认领
- 某个 AI 的开关读写、项目开关读写
- 消息：按项目分页读取（包括所有人的消息，不只是发给 human 的），以 human 身份发送，把 human 的消息标为已读
- **数据变化检测**：提供一个便宜的"数据是否变化"查询（比如 `PRAGMA data_version` 加上本进程的写入计数），给界面轮询用。

## 三、区分消息的来源（决策 12）
- 数据库版本 5：`messages` 表加一列 `via`，取值 `mcp`、`cli`、`gui`，旧数据填 `mcp`。
- AI 看到的消息里要标出 human 消息的来源：`human（软件界面）→ codex：…` 或 `human（命令行）→ codex：…`。AI 发的消息不加标注。`history` 的输出也一样。
- 在章程的公共规则里加一句：**来自"软件界面"的 human 消息才是用户本人确认过的指令**。先把这句加进 `templates/common.md`，由 Claude 审查。

## 四、自动发现项目（决策 13a、22）
- 从两个地方读取用户用过的项目，**只读、只取项目路径**：
  - Codex：`~/.codex/config.toml` 里的 `[projects.'<路径>']` 表头
  - Claude：`~/.claude.json` 顶层 `projects` 对象的键
- **合规红线（决策 22）**：`~/.claude.json` 里还有账号信息。解析时只取 `projects` 的键，其他字段不能保存、不能记日志、不能传给前端。**不能读 `~/.claude/.credentials.json`**，也不能读 Codex 的登录文件。要有测试证明：返回给前端的数据里只有路径。
- 发现的路径按 T06a 的规则换算成项目键，然后去重。已经在 Bridge 里的项目不重复显示。
- 左侧列表下面显示"发现的项目"（灰色、默认关闭），可以一键开启，也可以隐藏。被隐藏的项目记在本软件自己的设置文件里。
- **设置文件放在 `~/.bridge/app.json`**，不要放在 AppData（决策 27 的经验）。

## 五、主窗口（决策 30、31）
- 左侧：已开启的项目（开关、未读数的角标、未初始化的提示）→ "发现的项目" → "+ 添加项目"（用 dialog 插件选择文件夹）→ 底部的全局总开关。
- 右侧：选中的项目，标签页：
  - **公告板**：章程摘要（版本、模板、目标）、各方职务和每个 AI 的开关、各会话的状态卡片、当前认领。项目未初始化时，显示"待初始化，请在命令行执行 `bridge-mcp init …`"（向导在 T08b 做）。
  - **聊天**：按时间显示所有消息（区分 human、claude、codex、bridge，以及 human 消息的来源），底部输入框和收件人下拉框（all、claude、codex），以 `via=gui` 发送。进入聊天页时，把发给 human 的消息标为已读。
  - **历史**、**设置**：先放占位，写"将在 T08b 提供"。
- 外观：Fluent UI v9；Windows 11 上窗口背景用 Mica，不支持时退回纯色；跟随系统深浅色。
- **界面上的文字全部集中放在 `app/src/i18n/zh-CN.ts`**（决策 5），组件里不能直接写中文字符串。
- 界面每 1.5 秒轮询一次"数据是否变化"，有变化才重新读取。窗口隐藏时降到每 5 秒一次（托盘状态和通知仍然需要更新）。

## 六、托盘和通知（决策 32、33）
- 托盘图标三种状态：全局关闭（灰色）、正常（彩色）、有发给 human 的未读消息（带红点）。
- 左键单击：显示或隐藏主窗口。右键菜单：已开启和已发现的项目（勾选框，可以直接开关）→ 分隔线 → 全局总开关 → 打开主窗口 → 退出。
- 点窗口的 ×：隐藏到托盘；第一次这样做时弹一次提示"AI Bridge 仍在托盘运行"，然后记进 `app.json`，以后不再提示。
- **通知**：只有发给 human 或 all 的**新**消息，而且发送方是 AI 或 bridge 时才弹。点击通知打开主窗口并跳到这个项目的聊天页。已经通知过的最大消息 id 记在 `app.json` 里，重启软件后不会重复通知。
- 用 single-instance 插件保证只有一个实例：再次启动时，把已经在运行的那个窗口调出来。

## 七、测试
- **Rust**：结构化接口的单元测试；自动发现的测试（在临时目录里构造假的 `~/.codex/config.toml` 和 `~/.claude.json`，其中 `.claude.json` 里放一个假的 `oauthAccount` 字段，断言返回结果里完全没有它）；`via` 迁移和显示标注的测试。
- **契约测试**：AI 看到的 human 消息带来源标注；从版本 4 升级到版本 5。
- **前端**：`tsc --noEmit` 通过；用 vitest 测几个纯逻辑的函数（比如未读数计算、托盘状态判断、文字资源完整性，也就是界面上用到的每个键在 `zh-CN.ts` 里都有）。
- **CI**（Windows）：加上 `npm ci`、`tsc`、`vitest`、`vite build`，以及 `cargo build -p` 桌面应用。
