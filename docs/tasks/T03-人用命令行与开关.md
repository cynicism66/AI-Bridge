# T03：人用命令行与开关

## 背景
目前人只能用 `show` 只读地查看公告板。本任务做两件事：
1. **开关**：用户决定 Bridge 在哪些项目里启用。关闭时 AI 调用工具会立刻知道，然后照常工作，不再反复调用。
2. **人也参与协作**：人可以发消息、收消息，也可以实时盯着公告板。

用户已经拍板的设计：**新项目默认关闭**，需要手动开启；开关**按项目设置**，另外有一个**全局总开关**。

## 一、开关

### 规则
- 全局总开关默认**开**；每个项目的开关默认**关**。
- 只有全局开、并且项目也开时，这个项目才算启用。
- 开关存在数据库里，建一张新表（用 `CREATE TABLE IF NOT EXISTS`，不需要迁移机制，迁移是 T04 的内容）。
- 每次调用工具时都要读取开关，改完马上生效，不用重启任何 app。
- **不提供任何开关工具给 AI**。只有人能通过命令行开关。

### 关闭时工具的表现
- 除 `list_projects` 外，所有工具在项目未启用时，**不执行任何读写**，直接返回说明文字。**不要**设置 `isError`，否则 AI 可能反复重试：
  - 项目未开启：`Bridge 未在此项目开启（由用户控制）。请忽略协作规则，正常工作；本次会话不必再调用 Bridge 工具。`
  - 全局已关闭：`Bridge 已被用户全局关闭。请忽略协作规则，正常工作；本次会话不必再调用 Bridge 工具。`
- `list_projects` 在全局关闭时返回上面的全局关闭文字；全局开启时照常列出项目，并在每个项目后面标出"已开启"或"未开启"。
- 同步更新 `tools.py` 里的 `INSTRUCTIONS` 和 `RULES.md`：说明 Bridge 由用户控制开关，收到"未开启"或"已关闭"的提示后，本次会话就不要再调用 Bridge。

## 二、命令行
用标准库 `argparse` 重写 `cli.py`，设置子命令。`main(argv=None)` 要能接收参数列表，方便测试。

| 命令 | 作用 |
|---|---|
| `bridge`（无参数） | 启动 MCP 服务器。**全局配置依赖这个入口，行为不能变** |
| `bridge on [项目]` / `bridge off [项目]` | 开启或关闭某个项目 |
| `bridge on --global` / `bridge off --global` | 全局总开关 |
| `bridge status` | 显示全局开关状态，以及所有项目的开关状态和最近活动时间 |
| `bridge show [项目]` | 保留现有行为；输出里加一行显示该项目是否启用 |
| `bridge post [项目] 内容 [--to all\|claude\|codex]` | 以 `human` 身份发消息，默认发给 all |
| `bridge read [项目]` | 读取发给 human 的未读消息（收件人是 all 或 human），读后标为已读 |
| `bridge watch [项目] [--interval 秒]` | 持续显示新消息和状态变化（只显示变化，不要反复刷屏），默认 2 秒检查一次；按 Ctrl+C 正常退出，不打印 traceback |

- **项目参数都可以省略，省略时取当前目录**。因为是人在自己的终端里运行，命令行这一侧可以先把相对路径转成绝对路径，再交给 `norm_project`。AI 侧的工具仍然必须传绝对路径，这一点不变。
- `bridge on` 或 `bridge off` 的项目目录不存在时，要给出提示，但仍然允许设置（项目可能还没创建）。
- 人用命令在全局关闭或项目未开启时也能用（人要能查看、能发消息），只是在输出开头提示当前是关闭状态。

### AI 工具的配套修改
- `send_message` 的 `to` 参数说明改为：`收件人：claude / codex / human / all，默认 all`。
- 除此之外，工具的名称、参数和返回文字都保持 T02 的样子。

## 三、控制台输出（T02 审查遗留问题 2）
- 人用命令的中文输出，在以下情况都不能乱码：PowerShell 5.1、代码页为 936 的 cmd、Windows Terminal、重定向到文件（写成 UTF-8）。提示：输出到控制台时用文本流（Python 在 Windows 控制台上会走 Unicode API）；被重定向时再写 UTF-8。
- 输出管道被提前关闭（比如 `bridge show | Select-Object -First 3`）时安静退出，不打印 traceback。
- **MCP 服务器的 stdio 仍然严格按 UTF-8 字节读写，不要动。**
