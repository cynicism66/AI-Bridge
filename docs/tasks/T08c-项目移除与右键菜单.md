# T08c：项目移除与右键菜单（T08 补丁）

## 背景
用户在测试完 `D:\bridge-demo` 之后发现了两个问题：
1. **界面里没办法移除项目**，只能关掉开关，项目会一直留在"我的项目"列表里。
2. **右键弹出的是 WebView 浏览器自带的菜单**（返回、刷新、另存为、打印、更多工具），其中"刷新"会重新加载整个界面，"更多工具"里还能打开开发者工具。

用户的决定：DECISIONS 第 35、36 条。另外，顺带修复 T08b 验收时发现的路径显示不统一。

## 一、移除项目（决策 35）
在 bridge-core 里实现，命令行和界面都调用它：

**从列表移除**（命令行：`bridge-mcp forget [项目]`）
- 关闭这个项目的开关，并把它加进 `~/.bridge/app.json` 的隐藏列表；数据库里的数据全部保留。
- 自动发现的列表里也不再显示它。以后用"+ 添加项目"重新添加时，取消隐藏、恢复原来的状态（开关仍然是关的，由用户决定要不要再开）。
- 记录历史事件 `forget`。

**彻底删除**（命令行：`bridge-mcp purge [项目] --yes`，不加 `--yes` 时拒绝执行，并提示先用 `export` 导出）
- 在一个事务里删除这个项目在所有表里的数据：状态、会话、消息、已读记录、认领、开关、AI 开关、初始化信息、职务、权限覆盖、历史事件。按决策 35 的用户补充，`app.json` 仅保留软件内部隐藏标记，防止自动发现立即重新显示；不修改 Claude/Codex 的配置、项目或会话。手动添加可解除隐藏。
- **删除之前**：如果有 2 小时内活跃的会话，提示"有 AI 正在这个项目里工作"，界面上要求用户再确认一次（命令行需要额外加 `--force`）。
- 删除之后什么都不留，所以**不记录历史事件**。在删除确认框里要写清楚这一点。
- 如果这个项目用过"写入规则文件"，**不要去改项目里的 AGENTS.md、CLAUDE.md**，只在确认框里提示用户："项目文件夹里的 AGENTS.md / CLAUDE.md 仍有 Bridge 章程区块，如不需要请手动删除"。

**两种操作都不能碰项目文件夹里的任何文件。**

## 二、右键菜单和浏览器行为（决策 36）
- 在所有构建里**禁用 WebView 的默认右键菜单**；**正式版（release）**里还要禁用开发者工具，以及刷新（`F5`、`Ctrl+R`）、打印（`Ctrl+P`）、后退（`Alt+←`）等浏览器快捷键。调试版（debug）可以保留开发者工具，方便开发。
- 输入框和多行文本框里，保留 复制、剪切、粘贴、全选（可以用自定义菜单，也可以只保留系统快捷键，由你决定，在报告里说明）。
- **项目的右键菜单**（左侧"我的项目"里的每一项）：开启或关闭协作、在资源管理器中打开、从列表移除、彻底删除…（这一项放在最后，用红色）。
- **发现的项目的右键菜单**：开启协作、在资源管理器中打开、隐藏。
- "在资源管理器中打开"需要新的 Tauri 权限时，只开启打开**这一个文件夹**所需的最小权限（比如 opener 插件的 `reveal`，或者在 Rust 侧自己调用 `explorer.exe /select,…` 由命令触发）。**不要开放 shell 权限。** 新增依赖要在报告里说明。

## 三、路径显示统一（T08b 验收）
给人看的路径（交接预览、导出预览、提示信息等）统一用 Windows 风格：盘符大写、反斜杠，比如 `D:\bridge-demo\AGENTS.md`。内部的项目键不变（仍然是小写加正斜杠）。

## 四、测试
- **Rust**：`forget` 之后数据还在、重新添加后恢复；`purge` 删除所有表里的数据（用一个包含所有表数据的测试库，删除后逐表断言为 0），并且**不影响其他项目**的数据；有活跃会话时需要额外确认；两种操作都不碰项目文件夹（测试里在项目文件夹放文件，断言文件不变）。
- **契约测试**：`forget`、`purge` 命令的输出和报错；`purge` 不加 `--yes` 时拒绝执行。
- **前端**：右键菜单的逻辑（哪些项目显示哪些菜单项）。
- Windows CI 全绿。

## 完成报告

### 实现内容

- `forget` 核心、命令行和界面已接通：关闭项目开关、保存隐藏标记、记录 `forget` 历史，协作数据和项目文件保留；“+ 添加项目”取消隐藏并保留关闭状态。数据库事务与 app.json 原子文件替换配合，普通失败回滚；两者不构成跨存储的断电原子事务。
- 已加入两类项目右键菜单、彻底删除的两步确认框及活跃会话额外确认。`purge` 核心、CLI 和 Tauri 入口共用一个即时事务清理所有项目表，先删已读记录、最后删除事件，避免认领删除触发器留下历史。CLI 缺少 `--yes` 时拒绝并提示先导出，存在活跃会话时额外要求 `--force`。设置保存失败则数据库全部回滚，数据库提交失败则恢复设置。
- 窗口刷新同时监视 app.json，CLI 移除后界面会更新；界面保存通知设置时先读取最新配置，保留其他入口写入的隐藏列表。
- 默认右键菜单通过 WebView2 原生设置关闭；release 禁用开发者工具和浏览器加速键，前端同步阻止刷新、打印、后退等按键。文本编辑保留系统快捷键，不添加输入框自定义菜单。
- 资源管理器入口由 Rust 将一个已存在目录作为独立参数交给系统 explorer.exe，不经过 shell，未增加 Tauri shell/opener 能力。人用界面、命令行、导出及交接的 Windows 路径显示已统一，AI 内部项目键不变。
- 没有数据库迁移，版本仍是 6，没有对本项目执行移除、删除、初始化、职务或权限管理；真实安装程序未替换。

### 用户澄清及任务书调整

用户明确删除 AI Bridge 项目不能影响 Claude/Codex。实现仅在 Bridge 自己的 app.json 保留隐藏标记，项目的数据库协作记录全部删除；不修改两端配置、项目或会话，也不碰项目目录。手动添加时取消隐藏，被彻底删除的项目恢复为未初始化、开关关闭。原任务书“清除 app.json 相关记录”已据此调整为仅保留隐藏标记，决策 35、README 和确认框同步说明。

### 依赖及实现选择

- 新增直接依赖 `webview2-com = 0.39` 与别名 `webview2-core = { package = "windows-core", version = "0.62" }`。二者原先均已作为传递依赖存在于 Cargo.lock；前者调用 WebView2 Settings3，后者提供匹配版本的 COM Interface，与已有通知代码使用的 windows-core 0.61 分开。已在 Bridge #120 / #121 请 Claude 审查。
- [WebView2 Settings3 官方说明](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2settings3)规定，关闭浏览器加速键仍保留文本复制、剪切、粘贴和全选。隔离调试构建增加 `BRIDGE_UI_TEST_RELEASE`，仅在已有临时库和临时用户目录隔离条件满足时模拟 release 原生策略；正式版始终启用限制。
