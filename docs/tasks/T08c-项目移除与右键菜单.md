# T08c：项目移除与右键菜单（T08 补丁）

## 背景
用户在测试完 `D:\bridge-demo` 之后发现了两个问题：
1. **界面里没办法移除项目**，只能关掉开关，项目会一直留在"我的项目"列表里。
2. **右键弹出的是 WebView 浏览器自带的菜单**（返回、刷新、另存为、打印、更多工具），其中"刷新"会重新加载整个界面，"更多工具"里还能打开开发者工具。

用户的决定：DECISIONS 第 35、36 条。另外，顺带修复 T08b 验收时发现的路径显示不统一。

## 一、移除项目（决策 35）
在 bridge-core 里实现，命令行和界面都调用它：

**从列表移除**（命令行：`bridge-mcp forget [项目]`）
- 关闭这个项目的开关，并把它加进 `~/.bridge/app.json` 的隐藏列表；数据库里的数据全部保留。
- 自动发现的列表里也不再显示它。以后用"+ 添加项目"重新添加时，取消隐藏、恢复原来的状态（开关仍然是关的，由用户决定要不要再开）。
- 记录历史事件 `forget`。

**彻底删除**（命令行：`bridge-mcp purge [项目] --yes`，不加 `--yes` 时拒绝执行，并提示先用 `export` 导出）
- 在一个事务里删除这个项目在所有表里的数据：状态、会话、消息、已读记录、认领、开关、AI 开关、初始化信息、职务、权限覆盖、历史事件。按决策 35 的用户补充，`app.json` 仅保留软件内部隐藏标记，防止自动发现立即重新显示；不修改 Claude/Codex 的配置、项目或会话。手动添加可解除隐藏。
- **删除之前**：如果有 2 小时内活跃的会话，提示"有 AI 正在这个项目里工作"，界面上要求用户再确认一次（命令行需要额外加 `--force`）。
- 删除之后什么都不留，所以**不记录历史事件**。在删除确认框里要写清楚这一点。
- 如果这个项目用过"写入规则文件"，**不要去改项目里的 AGENTS.md、CLAUDE.md**，只在确认框里提示用户："项目文件夹里的 AGENTS.md / CLAUDE.md 仍有 Bridge 章程区块，如不需要请手动删除"。

**两种操作都不能碰项目文件夹里的任何文件。**

## 二、右键菜单和浏览器行为（决策 36）
- 在所有构建里**禁用 WebView 的默认右键菜单**；**正式版（release）**里还要禁用开发者工具，以及刷新（`F5`、`Ctrl+R`）、打印（`Ctrl+P`）、后退（`Alt+←`）等浏览器快捷键。调试版（debug）可以保留开发者工具，方便开发。
- 输入框和多行文本框里，保留 复制、剪切、粘贴、全选（可以用自定义菜单，也可以只保留系统快捷键，由你决定，在报告里说明）。
- **项目的右键菜单**（左侧"我的项目"里的每一项）：开启或关闭协作、在资源管理器中打开、从列表移除、彻底删除…（这一项放在最后，用红色）。
- **发现的项目的右键菜单**：开启协作、在资源管理器中打开、隐藏。
- "在资源管理器中打开"需要新的 Tauri 权限时，只开启打开**这一个文件夹**所需的最小权限（比如 opener 插件的 `reveal`，或者在 Rust 侧自己调用 `explorer.exe /select,…` 由命令触发）。**不要开放 shell 权限。** 新增依赖要在报告里说明。

- 修复：将主题变量放在 Provider 的 `.app-theme` / `.app-theme.dark` 上，页面布局放到内部唯一的 `.shell`。Portal 继续得到字体、Fluent 主题和自定义颜色变量，不再得到整页高度和布局。未改变菜单动作、删除确认、数据库、MCP 或两端配置。
