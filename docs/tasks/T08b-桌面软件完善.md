## 一、必须修复的问题（先做）
1. **会话编号复用后旧记录残留**（T08a 审查）：
   - 新会话分配到编号 n 时，在同一个事务里，把同一项目、同一 agent、编号 n、但属于其他会话的 status 行和 sessions 行清理掉（或者标记为已结束，由你决定，在报告里说明）。
   - 文字公告板和界面都只把 **2 小时内活跃**的会话显示为独立的卡片或段落，更早的折叠成"较早的会话（N）"，可以展开。
   - 契约测试要复现真实库里出现过的情况：legacy 会话、复用编号之后，`【claude #2】`下面显示的必须是当前会话自己的状态。
   - 用**真实库的副本**验证：修复后，公告板上每个编号只出现一次。
2. **托盘菜单太长**（T08a 验收）：只列出已开启的项目，显示文件夹名；同名的文件夹要加上上一级目录来区分。自动发现的项目只在主窗口里出现。
3. **`auth` 过度打码**（T07 复审）：`auth` 只在按 `_`、`-`、`.` 或大小写切分后的某一段**完全等于** `auth` 时才算命中（比如 `AUTH`、`auth_token`、`x-auth`、`authToken`），`author`、`authority` 不算。其他关键词的规则不变。补上单元测试：`author=`、`authority:` 不打码，`AUTH_TOKEN=`、`x-auth: …` 要打码。

## 二、协作初始化向导（决策 13）
- 什么时候出现：打开一个**未初始化**项目的开关时自动弹出；公告板上"待初始化"的提示旁边也有"开始初始化"按钮；已初始化的项目在设置里有"重新初始化"。
- 步骤：
  1. **参与的 AI**：勾选已知的 AI（在这个项目里出现过的，加上 claude、codex），也可以手动输入新的 AI 名字
  2. **模板**：任务书流程、结对流程、独立开发、自定义（选择一个 TOML 文件）；每个模板要显示简介和它有哪些职务位置
  3. **分配职务**：每个职务位置一个下拉框；必须全部分配，一个 AI 只能担任一个位置，不满足时"下一步"按钮不可用，并提示原因
  4. **项目目标**：多行文本，不能为空
  5. **选项**：是否把章程写进 AGENTS.md 和 CLAUDE.md（默认**开启**，理由是决策 19）；是否让规划方自动起步（默认开启）
  6. **预览**：显示将要生成的完整章程，确认后才执行
- 失败时（比如规则文件的标记块损坏）要显示 bridge-core 返回的中文错误，并且什么都不改。

## 三、职务和权限编辑（决策 14）
- 公告板"参与者与职务"里，每个 AI 旁边有职务下拉框；改动的规则和 T06b 的 `role` 命令一样（目标位置被占用时交换双方），改之前先确认。
- **编辑权限**：每个职务位置有一个"编辑权限"按钮，可以编辑 `allow`、`deny`（文字列表）和 `write` 规则（一行一条，保存前用 T06b 的规则校验，不合法就提示）。
  - 存成**项目级的覆盖设置**，不改模板文件：数据库版本 6，新表存"项目 + 职务位置"的覆盖内容，迁移文件 `migrations/006.sql`。
  - 保存后章程版本加 1，AI 下次查看公告板时会重新完整显示。记录历史事件 `permission`。如果项目用了写入规则文件，要同步更新标记块。
  - 命令行也要能做同样的事：`bridge-mcp permission [项目] <职务位置> --allow … --deny … --write …`（可以重复传），另外支持 `--reset`，恢复为模板默认值。

## 四、历史时间线（决策 20a）
- "历史"标签页：按时间倒序显示事件，每条都有图标和一句话描述（文字和 `history` 命令一致），可以展开看详情。
- 筛选：AI（多选）、事件类型（多选）、日期范围、关键词搜索（在事件描述里搜）。分页或者滚动加载，一次 100 条。
- 如果只拿到了按条数截取的结果，要在界面上提示"只显示了最近 N 条"，不能让人误以为那就是全部。

## 五、导出与交接（决策 20、21）
- 设置页里有"导出协作记录"和"交接给…"两个按钮。
- **导出**：选择输出路径（默认 `docs/bridge/协作记录.md`）→ 在界面里显示**打码后**的完整预览，以及打码统计 → 仓库有远程地址时，显示醒目的警告 → 点"确认写入"才写。
- **交接**：选择接手的 AI → 预览打码后的 HANDOVER.md，并列出交接会带来的所有变化（哪些 AI 会被关闭、释放多少个认领、转发多少条消息）→ 确认后执行。失败时回滚，并显示原因。
- 预览和写入之间，如果数据库或目标文件发生了变化，要拒绝写入并提示重新预览（T07 已有这个机制，界面要把提示显示出来）。

## 完成报告

### 实现内容

- 会话编号复用采用**同一事务清理旧拥有者的 status / sessions**，不删除事件历史，不把旧认领转给新会话。版本 6 迁移同时修复已有重复编号，按最后活跃时间、开始时间和行序保留最新拥有者。两小时内活跃会话正常显示，更早会话默认折叠；GUI 点击展开，MCP 使用 `include_older=true`，CLI 使用 `show --include-older`。
- 托盘仅显示已开启项目，使用文件夹名，同名时补上父目录。`auth` 改为分段匹配，`author` / `authority` 保留，其他关键词规则不变。
- 六步初始化向导覆盖参与者、自定义 TOML、职务唯一分配、非空目标、默认写规则与起步、完整章程确认。开关触发、公告板入口和设置页重新初始化均已接通。
- `permission_overrides` 保存项目职务覆盖；CLI 和 GUI 共用权限校验、章程更新、规则文件更新及 `permission` 历史事件。职务交换沿用原核心逻辑，新权限用于 AI 公告板和认领拦截。
- 历史按时间与事件 ID 倒序，支持 AI / 类型多选、日期、描述关键词，分页每次 100 条。关键词匹配在分页前分块扫描，不受最初 500 条限制；存在后续页时提示截取范围，过期分页请求不会混入刷新后的列表。
- 初始化、导出和交接采用核心中的预览对象。GUI 以一次性编号确认同一份预览，CLI 使用相同的 prepare / commit 流程；数据库或目标文件变化时拒绝写入，普通失败回滚。导出与交接显示打码正文、统计、远程仓库提示和变更摘要。
- 设置页支持当前模板及章程、重新初始化、导出、交接、通知开关、取消隐藏、重置关闭提示、数据库路径和版本。旧 app.json 缺少通知字段时默认开启；关闭或重新开启通知均不补弹积压消息。

### 实现选择和范围

- 没有新增 Rust 或 npm 依赖。Tauri 仅增加保存文件对话框的能力；新增界面文字集中在 `zh-CN.ts`，所有 Rust / TSX 文件均在任务要求的行数内。
- CLI 未指定的权限列表保留，已指定的列表整体替换，空白条目清理后可得到空列表；`--reset` 恢复初始化时保存的模板默认值，不能与列表参数混用。位置覆盖跟随位置，重新初始化或交接时清除旧覆盖并按新模板重建。中文 README 已说明。
- 测试使用临时数据库、项目和配置目录。debug 桌面仅在同时设置 `BRIDGE_UI_TEST`、`BRIDGE_DB`、`BRIDGE_APP_HOME` 时跳过系统通知注册，配合独立应用标识测试 WebView；release 仍使用正常注册流程。
- 真实桌面仍在运行，因此 release 桌面构建使用独立 `CARGO_TARGET_DIR=build/t08b-release`，没有覆盖运行中的旧程序。真实 MCP 安装和真实数据库升级留待用户退出应用后操作；没有对本项目执行初始化、改职务、权限编辑或交接。
- 既有前端构建仍提示单个压缩后 chunk 超过 500 kB，构建成功；本任务没有增加依赖或调整告警阈值。原生权限同步、安装包、自动更新均未实施。
