# T02：测试体系、CI 与审查遗留修复

## 背景
T01 只有 3 个冒烟测试。项目已经公开到 GitHub，后续每个任务都要改代码，需要一套能兜底的测试，以及每次推送自动在 Windows 和 Linux 上运行的 CI。
T01 审查还遗留了两个问题。另外，为了能在进程内测试，有两处全局状态要改成按调用读取。

## 一、代码修改（全部修改都必须有对应测试）

### 1. 数据库连接必须关闭（T01 审查问题 1）
`with sqlite3.connect(...) as conn` 只提交事务、不关闭连接。改成一个上下文管理器：正常时提交、异常时回滚，**无论如何都关闭连接**。所有 store 函数统一使用它。
验收方式：用 `python -X dev -W error -m unittest discover -s tests` 跑测试，不出现任何 `ResourceWarning`。另外，Windows 上连接没关时，临时目录会删不掉，测试里能直接暴露这个问题。

### 2. 版本号统一（T01 审查问题 2）
`serverInfo.version` 改为读取 `bridge_mcp.__version__`，删掉写死的 `1.0.0`。README 里对应的说明一起更新。

### 3. 去掉导入时读取的全局状态（为了可测试）
- `store.DB_PATH` 现在在导入模块时就读取了 `BRIDGE_DB`。改成每次建立连接时，由函数（如 `db_path()`）解析。
- `tools.AGENT` 同理，改成每次调用时读取 `BRIDGE_AGENT`（如 `current_agent()`）。
- 时间统一通过 `store.now()` 获取，测试里可以用 `unittest.mock.patch` 冻结或快进时间。
- 要求：这些改动完成后，测试可以在同一个进程里切换身份和数据库，不必每次都起子进程。

### 4. 两处明确的行为修正
- **拒绝相对路径的 project**：现在传 `"."` 或 `"src"` 会按服务器进程的工作目录解析，这个目录是 app 决定的，无法预测，结果会悄悄写进错误的项目。改为：不是绝对路径就报错，错误提示要说明必须传项目根目录的绝对路径。
- **文件路径消除 `.` 和 `..`**：`src/../src/a.py`、`./src/./a.py` 都应当规范成 `src/a.py`（使用 `posixpath.normpath`）。规范化后如果跳出了项目根目录（以 `../` 开头），就保留规范化后的结果，不报错。

除以上四点外，工具的名称、参数和返回文字都不要改。

## 二、测试
按模块拆分成下列测试文件。每个测试使用独立的临时数据库，并在测试结束后清理干净：

| 文件 | 至少覆盖 |
|---|---|
| `tests/test_paths.py` | 大小写、反斜杠、结尾斜杠、`./` 前缀、`..` 消除、项目内的绝对路径转成相对路径、项目外的绝对路径、不同盘符、空值和相对 project 报错 |
| `tests/test_store.py` | 状态覆盖更新；消息只对收件人和 `all` 可见；自己发的消息不算自己的未读；已读按身份分别记录；`include_read` 的 limit 和排序；项目之间数据隔离；`list_projects` 按最近活动排序 |
| `tests/test_claims.py` | 整批认领有冲突时一个都不写入；同一身份重复认领会续期；到期后自动失效（用 mock 快进时间，**不许 sleep**）；只能释放自己的认领；不传 files 时释放全部 |
| `tests/test_server.py` | 在进程内调用 `handle()`：initialize 原样回显 protocolVersion、ping、未知方法返回 -32601、未知工具返回 isError、工具抛异常时返回 isError 并带中文说明、通知（没有 id）不回复、非法 JSON 返回 -32700 |
| `tests/test_smoke.py` | 保留现有测试，另加一项：**同一个子进程里连续发送** initialize、initialized 通知、tools/list、两次 tools/call，确认按顺序得到 4 个响应。真实客户端就是这样用的，现有测试是每个请求单独启动一个进程，覆盖不到这种情况 |
| `tests/test_concurrency.py` | 两个线程（或进程）分别以 claude 和 codex 身份，同时对同一个数据库各写 50 次状态和消息，不出现 `database is locked`，数据条数正确 |

测试可以使用 `unittest.mock`，但**不要**为了方便测试而改变产品行为。

后续留意（不阻塞，放进 T04）：
1. **不同 Python 版本处理 Git Bash 风格路径的结果不一样**：`/d/Bridge` 这种路径，在 Windows 的 Python 3.13+ 上 `isabs` 返回 False，会被拒绝，这是对的；但在 3.10–3.12 上返回 True，`abspath` 会把它解析成"当前盘符:\d\Bridge"，悄悄写进错误的项目。建议在 Windows 上明确要求 project 带盘符或是 UNC 路径，或者把 `/d/...` 转换成 `D:/...`。
2. 待核实：`show` 直接把 UTF-8 字节写到控制台，在代码页为 936 的控制台上可能乱码；输出管道提前关闭时退出码是 255。T03 做人用的命令行时一并处理。
