# T08g："等你处理"提醒

## 背景
Codex 卡在等用户授权时，用户在 Codex 窗口里看不到任何提示，完全不知道它卡住了（Codex 定时检查那一轮的回复不一定会出现在用户看的聊天窗口里）。Codex 发给 human 的消息，也因为用户正开着 Bridge 的聊天页，2 秒后就被自动标成了已读，没有引起注意。
我们控制不了 Codex app 的界面，所以由 Bridge 负责提醒（决策 41）。

## 一、什么算"等你处理"
1. **需要处理的消息**：`send_message` 新增一个可选参数 `needs_action`（布尔值，默认 false；工具说明写成"需要用户处理（确认、授权、决定）时设为 true"）。只有发给 `human` 的消息才能设置，其他收件人设置时报错。这条消息会一直处于"待处理"，直到用户在界面里点"已处理"，或者在这个项目里给这个 AI 回复了消息（以回复时间晚于这条消息为准）。
2. **卡点**：某个会话在 2 小时内活跃，而且它最新状态的"卡点"不为空，就算"待处理"。AI 把卡点清空，它就自动消失；用户也可以点"已知道"把它隐藏，直到卡点内容发生变化。
- 数据库版本 8：保存消息的 `needs_action` 标记和"已处理"时间，以及卡点的"已知道"记录（具体表结构由你设计，写进报告）。已处理和已知道都记入历史事件。

## 二、界面
- **横幅**：主窗口右侧顶部（项目标题上方）显示横幅，比如"codex 在等你：需要在 Codex 窗口里说『确认授权：先做 T08f，再做 T08e』"，旁边是"已处理"或"已知道"按钮，还有一个"查看"按钮（跳到对应的消息或公告板）。有多条时显示条数，可以展开。**无论当前开着哪个标签页，只要还没处理，横幅就一直显示。**
- 左侧项目列表里，有待处理事项的项目显示橙色标记。
- **托盘**：有待处理事项时，图标显示橙色标记（和"有未读消息"的红点区分开），托盘提示文字写"N 件事等你处理"。
- **通知**：出现新的待处理事项时弹 Windows 通知，**即使主窗口开着、聊天页也开着**；点通知就打开窗口，并定位到横幅。
- 界面文字放在 `zh-CN.ts` 里。

## 三、规则同步
- 在 `templates/common.md` 的公共协作规则里加一句（以后新初始化的项目都会有）："卡住或需要用户确认、授权时，在公告板上发消息给 human，并设置 needs_action=true，把需要用户做的事写清楚；同时在状态的卡点里填写。"
- README 说明这个提醒是怎么工作的。
- `AGENTS.md` 的工作流程第 5 条已经由 Claude 加上，你只需要把"设置 needs_action=true"补进去。

## 测试
- 契约测试：`needs_action` 参数（发给 human 时可以设置，发给其他收件人时报错）；待处理的产生和消失（用户回复、用户点已处理）；卡点的产生、"已知道"、卡点内容变化后重新出现；从版本 7 升级到版本 8。
- 前端测试：横幅在各个标签页都显示；托盘状态的判断（橙色标记和红点的优先级）。
- Windows CI 全绿。

## 验收
部署后，由 Claude 发一条 `needs_action=true` 的测试消息给 human。用户确认：弹出了通知；横幅出现，而且切换标签页后仍然在；托盘图标有橙色标记；点"已处理"后横幅消失。然后再测一次卡点：Codex 在状态里填一个测试用的卡点，横幅出现；Codex 清空卡点后，横幅消失。
