### 2. 目录结构
```
D:\Bridge\
├─ bridge.py              # 兼容入口，只保留几行：把 src 加进 sys.path，然后调用 bridge_mcp 的 main
├─ pyproject.toml         # 包名 bridge-mcp，无依赖，requires-python >= 3.10，命令行入口 bridge = bridge_mcp.cli:main
├─ README.md              # 中文：是什么、怎么配置到 Claude/Codex、怎么用命令行查看
├─ src/bridge_mcp/
│  ├─ __init__.py         # __version__ = "0.1.0"
│  ├─ __main__.py         # 支持 python -m bridge_mcp
│  ├─ store.py            # 数据库连接、建表、所有读写操作；返回 dict / list，不做任何文字格式化
│  ├─ tools.py            # 7 个工具的定义（名称、说明、参数 schema）和实现：调用 store，把结果格式化成中文文字
│  ├─ server.py           # MCP 协议：JSON-RPC over stdio，initialize / ping / tools/list / tools/call
│  ├─ cli.py              # 命令行：无参数时启动 MCP 服务器；show [项目路径] 打印公告板
│  └─ paths.py            # 项目路径、文件路径的规范化（norm_project / norm_file）
└─ tests/
   └─ test_smoke.py       # 冒烟测试，见下文
```
模块依赖方向：`cli → server → tools → store / paths`，不要反向引用。

### 3. 唯一的行为变更：默认数据库位置
- 原来：`bridge.py` 同目录下的 `bridge.db`。拆分后 `__file__` 位置变了，这个规则不再合理。
- 改为：`BRIDGE_DB` 环境变量优先；否则用 `Path.home() / ".bridge" / "bridge.db"`，目录不存在就自动创建。
- 注意：这台机器的 `HOME` 环境变量被设成了 `D:\Cadence\home`。`Path.home()` 在 Windows 上读的是 `USERPROFILE`，所以不受影响。**不要自己去读 `HOME`。**
