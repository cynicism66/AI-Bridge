# T08f：聊天输入框修复（小补丁）

## 背景
用户反馈两个问题（决策 40）：
1. **输入框右下角的拖动柄有 bug**。`Chat.tsx` 里的 Fluent `Textarea` 设置了 `resize="vertical"`，而拖动柄调整的是内层的 `<textarea>`，外层 `.fui-Textarea`（在 `.composer>.fui-Textarea` 里设置了 `min-height: 85px`）不会跟着一起变化，也没有最大高度。拖动之后会出现拖不小、无限变大、把消息列表挤没、布局错乱等情况。**请在用户自己启动的正式版里先复现，确认具体表现后写进报告。**
2. **回车只能换行，不能发送。** 用户希望按回车发送。

## 要做的事
1. **去掉拖动柄**（`resize="none"`），改为**随内容自动长高**：最少 3 行，最多约 8 行，超过后在输入框内部滚动；不能把消息列表挤没。发送成功后恢复到最小高度。
2. **按键**：
   - `Enter` 发送；`Shift+Enter` 换行
   - **中文输入法组词时按 Enter 不发送**（判断 `event.nativeEvent.isComposing`，或者 `keyCode === 229`），只完成选字。这一点对中文用户至关重要，必须有测试覆盖
   - 内容为空或者只有空白时，按 Enter 不发送，也不换行
   - 正在发送时按 Enter 不会重复发送
3. 占位提示的末尾加上"（Enter 发送，Shift+Enter 换行）"，文字仍然放在 `zh-CN.ts` 里。

## 测试
- 前端单元测试：Enter 发送；Shift+Enter 不发送；输入法组词时（`isComposing=true`）Enter 不发送；内容为空时不发送；发送中不重复发送；自动长高的上下限。
- Windows CI 全绿。

## 验收
部署（只需要重新编译桌面程序，不用重装 MCP，也不用退出 Claude 和 Codex）之后，用户确认：输入框没有拖动柄；打字时会自动长高，到了上限就在框内滚动；用中文输入法打字、按回车选词时不会误发；Enter 发送，Shift+Enter 换行。

## 不要做
- 不改后端和数据库；不做其他界面改动。


## 完成报告（Codex）
- 将输入区独立为 `Composer`，移除拖动柄，按实际内容高度限制为 3–8 行；宽度变化时重新计算，超过上限内部滚动，发送成功恢复最小高度。消息区允许收缩但输入区不无限长高。
- Enter 发送、Shift+Enter 保留换行；`isComposing` 与 `keyCode=229` 均跳过发送。空白 Enter 阻止换行；同步锁阻止同一事件周期和发送过程中的重复提交；失败保留草稿。提示集中在中文资源文件。
- 验证：25 项前端测试、TypeScript/Vite 生产构建通过；Rust fmt、Clippy 和 47 项测试通过。隔离 Edge 深浅主题验证实际 3–8 行高度、超限内部滚动、消息区保留、IME/换行/发送及成功后恢复高度，均通过。测试全部使用模拟数据。
- 正式版原问题复现：本机 computer-use 连续报 `trusted Node process exited unexpectedly`，未能操作用户已启动的正式版；已向 human 请求补充原版拖动表现。当前仅确认源代码存在内层 `resize=vertical` 与外层最小高度的组合，不能将代码推断或隔离测试写成真实正式版复现。
- 未改后端、数据库或 MCP，无新增依赖。Windows CI、Claude 审查和用户部署验收待完成后补记；部署只需退出 AI Bridge 托盘、重新编译桌面并独立启动，Claude/Codex 无需退出。

## 审查意见（Claude，代码审查）
**结论：代码审查通过。** 还差 Windows CI 结果和用户部署验收。

建议（不阻塞）：发送的时候输入框被禁用，发送完成后焦点可能会丢失，用户需要重新点一下才能继续打字。以后可以在发送成功后自动把焦点放回输入框。
